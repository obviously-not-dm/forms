# Тренажёры по дискретной математике

Тесты пишутся в Markdown, сборка превращает их в статический сайт на GitHub Pages. Попытки студентов сохраняются в Supabase, статистика — на `/admin.html`.

```
content/site.yml          название сайта, группы, ключи Supabase
content/<id>/test.md      тест; <id> попадёт в ссылку: /<id>/
content/<id>/*.png        картинки теста
content/<id>/figures.py   скрипт картинок через dm_figures (для себя, на сайт не идёт)
figures/dm_figures.py     модуль картинок
src/                      вёрстка и скрипты сайта
build.mjs                 сборка
supabase/schema.sql       таблицы и права
```

## Запуск

Нужен Node 20+.

```
npm install
npm run dev      # http://localhost:8000, пересобирается при сохранении
npm run build    # только собрать в dist/
```

Если в тесте ошибка, сборка падает и перечисляет все места сразу: «bo-2, задание 14: одиночный выбор, а отмечено верных: 2». На сайт тест с битым ключом не попадёт.

## Формат теста

```markdown
---
title: Бинарные отношения, лекция 2
description: |
  Тест для подготовки к контрольной. Баллы не ставятся.
feedback: Что было непонятно на практике? Необязательно
order: 3          # место в списке на главной
hidden: false     # true — собрать, но не показывать на главной (для ревью по ссылке)
---

# Блок 1. Один верный вариант

## 1

R = {(1, 2), (2, 3), (3, 3)} на A = {1, 2, 3}. Какие свойства есть у R?

![Граф отношения](q1.png)

- ( ) рефлексивно
- (x) ни одного из перечисленных
- ( ) симметрично
- ( ) транзитивно

Подсказка: Проверьте каждое свойство по определению, начиная с рефлексивности.
Подсказка: Для транзитивности посмотрите на пары (1, 2) и (2, 3).

Пояснение:
Ответ: ни одного из перечисленных.

1. Нет пары (1, 1) — не рефлексивно.
2. ...

# Блок 2. Краткий ответ

## 12

R = {(1, 2), (1, 4), (3, 2)}. Im(R) = ?

Формат: {элементы по возрастанию через запятую}
Ответ: {2, 4}

Пояснение:
...

# Блок 3. Несколько верных вариантов

## 30

...

- [x] вариант
- [ ] вариант
- [x] ![А](q30_А.png)
```

Правила:
- `# ` — блок, `## ` — задание. Число после `##` — номер задания, по нему ищутся ошибки при сборке и строится статистика. Номер на сайте ставится по порядку.
- `- ( )` / `- (x)` — одиночный выбор, `- [ ]` / `- [x]` — множественный. По форме скобок студент видит, сколько можно выбрать: кружок или квадрат.
- `Ответ:` вместо вариантов — краткий ответ. Строк `Ответ:` может быть несколько, если верных записей несколько по смыслу (например, два синонима). Пробелы, регистр, ё/е, кириллица вместо похожей латиницы и `∅` вместо `{}` уже учитываются. Если все ответы — числа, сравнение числовое; если множества `{…}` — без учёта порядка элементов.
- `Формат:` обязателен для краткого ответа.
- `Подсказка:` — сколько угодно, открываются по одной. В статистике видно, на каких заданиях их брали.
- `Пояснение:` — всё до следующего задания. Можно списки, картинки, таблицы, `**жирный**`.
- Обратный слеш разности пишется с пробелами: `A \ B`. Без пробела перед скобкой или звёздочкой (`\(`, `\*`) Markdown его съест.
- Markdown работает везде: в условии, вариантах, формате, подсказках и пояснении. Можно `**жирный**`, списки, таблицы, `<sub>R</sub>`.

## Как оформлять пояснение

Так устроены пояснения в `content/bo-4`, на сайте это выглядит ровно и читается с телефона:

```markdown
Пояснение:
**Ответ:** Б, Г.

> **Слайд 9.** «цитата со слайда»
>
> **Слайд 46.** Своими словами, если цитаты нет.

- **Б.** Почему верно.
- **А** неверно. Почему.
```

Блок `>` — опора на лекцию, он выделен фоном. Разбор вариантов — список, выкладки — нумерованный список или таблица, длинные цепочки равносильностей — `$$\begin{aligned} … \end{aligned}$$`. Цитаты со слайдов остаются дословными, формулы в них можно не переводить в KaTeX.

## Формулы

KaTeX, рендерится при сборке: на сайт уходит готовый HTML, скриптов у студента нет.

```markdown
$A = \{1, 2, 3\}$. $|\mathcal{P}(A)| = ?$      формула в строке

$$R^{-1} = \{(b, a) \mid (a, b) \in R\}$$        отдельной строкой
```

Работает в условии, вариантах (`- (x) $R \circ S$`), подсказках, пояснении и описании теста. Ошибка в формуле — ошибка сборки с номером задания. Unicode-формулы вроде `R ⊆ A²` тоже остаются, их можно смешивать. Внутри `$…$` фигурные скобки множества экранируются: `\{1, 2\}`. Ответ краткого ответа по-прежнему набирается с клавиатуры, поэтому `Ответ:` — обычный текст, не KaTeX.

## Картинки

Через `figures/dm_figures.py`, прямо в папку теста:

```
cd content/bo-2
python3 figures.py
```

Рисуйте в SVG: `venn(..., path="q14.svg")`. SVG векторный, с прозрачным фоном и сам перекрашивается в тёмной теме: чёрные линии становятся светлыми, белые вершины тёмными, фиолетовая заливка остаётся фиолетовой, только темнее. Переключать ничего не нужно, картинка следует теме телефона.

Старые PNG тоже работают: в тёмной теме сайт затемняет их фильтром (белое → тёмно-серое, чёрное → светлое, оттенки сохраняются). Так что перерисовывать уже готовые тесты не обязательно.

В тексте теста — обычная ссылка `![подпись](q14.svg)`. Подпись читают экранные дикторы, пишите в ней, что на картинке. Картинка-вариант — `- [x] ![А](q14_А.svg)`, такие варианты выводятся сеткой 2×2.

Фотографии: JPG и WEBP показываются как есть. PNG-фото, которое не нужно затемнять, подпишите заголовком `![Доска с лекции](board.png "фото")`.

## Supabase

1. Создать проект. SQL Editor → вставить `supabase/schema.sql` → Run. Повторный запуск безопасен, так же обновляется схема.
2. Authentication → Sign In / Providers → выключить регистрацию новых пользователей. Authentication → Users → Add user для каждого преподавателя и ментора, которым нужна статистика. Потом:
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'почта@itmo.ru';
   ```
3. Project Settings → API Keys → Project URL и publishable-ключ (в старых проектах — `anon`) в `content/site.yml`. Этот ключ публичный: с ним можно только добавить попытку, читать может только админ. Секретный ключ в репозиторий не класть.

Без ключей сайт работает, но попытки никуда не пишутся — удобно для проверки нового теста.

## GitHub Pages

Settings → Pages → Source: **GitHub Actions**. Дальше каждый пуш в `main` собирает и выкладывает сайт (`.github/workflows/pages.yml`), через минуту изменения на `https://<логин>.github.io/<репозиторий>/`. Если в тесте ошибка, сборка в Actions упадёт с тем же списком, а на сайте останется прошлая версия.

## Что стоит знать

- **Ключи и разбор лежат в `/<id>/key.json`.** Страница загружает его только после отправки, но при желании его можно открыть руками. Для самопроверки без баллов это приемлемо. Закрыть можно, перенеся проверку в SQL-функцию Supabase.
- **Бесплатный Supabase засыпает** после недели без запросов. Тесты открываются, но попытки не сохраняются, пока проект не разбудить в панели.
- **Прогресс хранится в браузере студента**: ответы переживают перезагрузку, на главной видно «в процессе» и последний результат. С другого устройства этого не видно.
- **Статистика перепроверяет попытки по текущему ключу.** Исправили ключ — цифры пересчитались. Столбец «частые неверные ответы» помогает найти такие ошибки: если много людей пишут одно и то же, возможно, это тоже верно.
